# Phase 14 — PDF Generation Redesign

## Outcome

Phase 14 generates polished diet and workout PDFs directly from current persisted plan data. English and Arabic are selectable per request, preview and download use distinct HTTP content-disposition behavior, and generated bytes remain in memory rather than being written to deployment-server storage.

## Engine abstraction and portability

`PlanPdfService` owns plan retrieval, client metadata, language selection, and friendly filenames. `IPlanPdfRenderer` isolates the rendering engine in Infrastructure. The implementation uses QuestPDF, matching the legacy project’s selected engine and Community license configuration; deployment owners must reassess the configured license if their eligibility changes.

Noto Sans Arabic is embedded in the Infrastructure assembly so Arabic shaping does not depend on operating-system fonts. The font and included `OFL.txt` are distributed under the SIL Open Font License 1.1.

The renderer returns a byte array only. It has no saved-plan directory, temporary-file path, web-root write, or file persistence API.

## Language behavior

`PlanPdfLanguage` supports English and Arabic. English is the default. For bilingual plan, version, meal, day, food, exercise, and replacement names:

- English output uses the required English value;
- Arabic output uses the Arabic value when meaningful;
- Arabic output consistently falls back to required English when Arabic is absent.

The embedded font supports Arabic and Latin together, so mixed fallback text remains readable.

## Output rules

Only active plan notes are rendered. Diet output includes only versions marked active for PDF. Day, meal, version, and exercise-scoped content remains visible when supplied.

Optional columns are decided before a table is rendered. A workout column for sets, repetitions, rest, tempo, RPE/RIR, exercise notes, or video appears when at least one exercise in that day contains a meaningful value. A food-note column appears when at least one food row in that meal has a note. Empty cells remain empty when another row requires the column; the column is never removed per row.

Diet PDFs include prescribed totals and structured alternatives without double-counting alternatives. Workout PDFs include current exercise names, prescription values, and clickable video links.

## API

All routes require the administrator role.

- `GET /api/diet-plans/{id}/pdf/preview?language=English|Arabic`
- `GET /api/diet-plans/{id}/pdf/download?language=English|Arabic`
- `GET /api/workout-plans/{id}/pdf/preview?language=English|Arabic`
- `GET /api/workout-plans/{id}/pdf/download?language=English|Arabic`

Preview returns `Content-Disposition: inline`; download returns `attachment` with stable names such as `Performance-Diet-diet-plan-en.pdf`.

## Visual design

The redesign follows the downloaded TailAdmin/Next.js template’s visual system: brand `#465FFF`, pale-blue summary surfaces, gray borders, white cards, compact metric blocks, rounded sections, and restrained typography. It does not copy React components or runtime code.

## Verification

Automated tests cover bilingual fallback, whole-table optional-column decisions, authorization, preview/download headers, user-friendly filenames, valid PDF signatures, and the absence of generated PDFs from the server output tree.

Representative English and Arabic diet/workout PDFs were generated to `tmp/pdfs`, inspected with `pdfinfo`, checked with text extraction, rendered at 130 DPI with Poppler, and visually reviewed page by page. All were A4 PDFs with aligned content, readable Arabic/English text, correct active-note/version filtering, conditional columns, and clean page furniture. QA intermediates are not committed.
